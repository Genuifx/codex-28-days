## 1. 目标与范围

让访客更容易搜索到某条更新、把它分享给别人，并通过 RSS 回访。保留现有像素风首页和完整时间线，增加中英独立详情页、来源明确的短标题、一张通用分享预览图及免费 RSS。

**视觉与交互硬约束：沿用当前站点，只加增量部分。** 复用现有配色、字体、卡片样式、布局、间距和交互，不做整体改版，不重设首页主视觉。详情页、通用 OG 分享图和 RSS 入口都使用现有视觉语言；只为新增标题、内容和入口作最小必要扩展，不借本批重排既有模块或统一替换样式。

继续使用现有 Python 静态生成、GitHub Actions 和 GitHub Pages；不引入新外部服务、账号体系、付费订阅、邮箱收集、统计服务或自动对外发帖。保留现有 Cloudflare 统计，以页面路径观察详情页访问；本批不依赖 UTM 或自定义事件。

## 2. 内容与数据不变量

基线含 18 条 entries、4 条 resets 记录、4 条嵌套作者 follow-ups。entries 与 resets 的 ID 去重后共 20 个顶层帖子 ID；这是数据保护口径，不是详情页数量。

- 本批只调整展示与生成结构，不新增、删除、合并或重新分类这些原始记录。既有 ID、原文、译文、引用帖、来源 URL、日期与 follow-up 归属全部保留。
- 18 条 entries 各有一组中英详情页，含 kickoff、同日多条和 reset。follow-ups 与引用帖继续附在所属条目内，不扩大 Day 计数；独立 resets 数据继续完整保存在原 JSON。
- 离线构建不得改写 data/days.json。基线文件 SHA-256 为 c86895d553ff78b818c95883ebb6a0a4171c0e9935d78d232f1b83b2c7cc7c54。日常抓取仍可按现有规则保存后来核实的新内容，不把历史快照当作永久数量上限。

## 3. 页面、链接与语言

- 英文首页：/；中文首页：/zh/。
- 英文详情：/updates/{X-post-id}/；中文详情：/zh/updates/{X-post-id}/。每个路径输出自己的 index.html，以不可变帖子 ID 为键，标题、Day 或 qualifier 改动不会改变 URL。
- 当前快照共 38 个 HTML 页面：2 个首页、36 个详情页。新增内容以后由数据驱动扩展，不能硬编码 18。
- 首页现有 #day-* 锚点全部保留，包括 #day-3-encore、#day-5-dots-edition；已有引用和 follow-up 锚点也保留。不会把旧链接改成失效页面。
- 首页卡片增加主题标题链接。详情页显示标题、发布时间、完整内容、原帖出处、引用与补充、前后条目及返回时间线入口。保留非官方网站和机器翻译提示。
- 保留现有中英切换控件的外观、位置和操作方式，底层改为对应页面的真实链接，无 JavaScript 仍可用；URL 决定当前语言，不被浏览器语言或存储偏好覆盖，也不自动跳转。每页静态输出对应语言的标题、正文和元数据。
- 每个页面的 canonical 指向自身；中英版本双向标注 hreflang，英文为 x-default。sitemap 只列真实页面 URL，不列锚点；llms.txt 改用详情链接。
- 翻译缺失的统一回退规则：中文页面及中文 RSS 对缺失段落显示英文原文，并明确标注“暂无中文译文”；英文回退段落标记 lang="en"，其他已有译文照常保留。页面和 URL 始终可读，不因翻译缺失切换 noindex 状态或临时重定向；翻译补齐后更新同一页面。

## 4. 标题、分享图与 RSS

主题标题是对已保存来源的简明概括，不补写来源没有支持的功能、数值或适用人群。18 条首发标题逐条核对，保存中英标题与依据的帖子 ID；原文不被标题替代。示例：Day 2.2“OpenAI API 使用档位调整”依据所引用的 OpenAI Developers 帖；Day 7“GPT-6.1 Sol 默认上下文增至 500k”依据作者原帖。Reset 如实标明，Day 10 的开场玩笑不能误作功能标题。新条目尚无编辑标题时使用保守来源摘录，不阻塞更新。

首页、详情 H1、浏览器标题、分享文案、结构化数据与 RSS 使用同一份标题来源。详情页标题不能被现有语言脚本改回首页标题。

新增一张沿用站点视觉的 1200×630 静态 PNG，保存于 assets/og/cover.png；所有页面提供绝对地址的 og:image、twitter:image、图片说明及 summary_large_image。图中不嵌入会频繁变化的最新 Day 数。现有 Canvas 海报保留；新分享、复制、原生分享和海报二维码统一指向当前语种的准确详情页，继续满足“同日不同条目不能串链”的既有修复要求。

RSS 地址为 /feed.xml 和 /zh/feed.xml，每个 entry 对应一项，按发布时间倒序，含主题标题、短摘要、来源发布时间、详情链接与原帖链接。GUID 由帖子 ID 和语种组成且保持不变；follow-up 更新父条目内容，不重复发布为新的 Day。首页和详情增量添加可见订阅入口，复用现有链接或按钮样式，并提供 RSS 自动发现标签。不虚构最近修改时间；缺乏可靠依据时省略可选的 lastBuildDate / lastmod。

## 5. 生成链路与边界

抓取和翻译继续保存到 data/days.json；独立的标题映射放入 data/titles.json。静态生成读取这两份数据，复用同一套内容渲染，输出首页、详情页、RSS、sitemap 和 llms.txt；通用 PNG 随仓库发布，不依赖运行时制图服务。

在现有 scripts/scrape.py 的渲染职责内统一 URL、标题、语言与分享信息，新增离线构建入口，支持在临时目录只用已有数据重建全部产物。原始内容、HTML 属性、JSON 脚本和 XML 分别正确转义；原始数据链接使用根路径，避免嵌套页面相对路径失效。

现有每日任务的正常提交路径及冲突后重建路径都必须包含新增产物。构建失败不发布半套页面；相同输入重复构建应得到相同文件，不因当前时钟反复制造更新。保留抓取异常时不丢历史数据的现有行为。

## 6. 测试与部署验收

实现完成后，全部满足以下条件才可报告上线完成：

1. 原有回归测试通过；固定基线离线构建前后 JSON 字节不变，20 个顶层 ID 集合、18 个 entries 及 4 条 follow-ups 的归属均一致，原文和引用内容完整。
2. 所有详情 URL 唯一且有对应文件；同日多条、子编号、kickoff、reset、带开场文字的 Day 10 均正确。首页所有既有锚点仍有效。
3. 中英页面无 JS 可读、可切换；标题、canonical、hreflang、结构化数据及各分享入口对应同一条目与语种。翻译缺失按明确规则回退。
4. 两份 RSS 可按 XML 解析，GUID 稳定、日期有效、字符转义正确；sitemap 中每个 URL 可访问；PNG 尺寸正确、文件非空。
5. 同输入连续重建两次，全部生成产物字节一致；离线重建不发起抓取或翻译请求。手机与桌面检查语言切换、返回/前进、复制和海报重复开关。
6. 对照当前首页基线截图做桌面、手机及中英两种语言的视觉回归。截图差异应能逐项归因于新增标题、RSS 入口及其必要占位；既有配色、字体、卡片、主视觉、模块顺序、间距规则和操作保持一致。新增详情页与 OG 图也需核对是否沿用现有视觉；不接受整体改版。
7. 发布前确认目标提交包含全部生成文件且通过测试。发布后核对该提交的 Pages 部署成功，再实际请求首页、两语详情、两个特殊同日条目、PNG、RSS 和 sitemap；检查 HTTP 成功状态、内容与链接。远端若已有新数据，先保留并重新生成，不用旧快照覆盖。

## 7. 风险与效果判断

独立 URL 增加可被发现和分享的入口，RSS 提供回访渠道；这些能力不保证搜索收录、排名或流量增长。短 Reset 页可能没有独立搜索价值；译文回退和现有机器翻译可能影响阅读质量，社交平台也可能缓存旧预览。维护来源真实性和旧链接兼容性优先于追求标题吸引力。

上线后的观察使用现有统计的页面访问与来源变化，保持相近时间窗口；不把页面数量、RSS 请求量或一次访问变化等同于真实增长。首批不扩展到账号、邮件订阅、外部推广或新统计系统。
